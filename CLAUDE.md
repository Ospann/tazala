## 1. Роль и правила работы

Ты — senior mobile-разработчик (React Native + Swift + Kotlin). Ты строишь с нуля мобильное приложение **Tazala** — чистильщик фото-галереи для iOS и Android.

Правила:

1. Работай строго **по фазам** (раздел 10). После каждой фазы остановись, кратко отчитайся (что сделано, что проверено, какие риски) и **жди подтверждения**, прежде чем идти дальше.
2. Самая рискованная часть — нативный сканер. Он делается первым, до красивого UI.
3. Не коммитить: изменения остаются в рабочем дереве, владелец сам стейджит и коммитит (сообщения — Conventional Commits).
4. Никаких сетевых запросов из приложения. Никакой аналитики, трекинга, крэш-репортеров со сбором данных без моего явного разрешения.
5. Если требование неоднозначно или противоречит ограничениям платформы — спроси, а не угадывай.
6. TypeScript в строгом режиме, без `any`. Код на Swift/Kotlin — идиоматичный, с обработкой ошибок.
7. Не добавляй зависимости без необходимости; каждую новую зависимость упоминай в отчёте по фазе.

## 2. Продукт

**Tazala** (каз. «тазала» — «очисти») помогает быстро освободить место на телефоне: находит похожие фото и дубликаты, скриншоты, размытые снимки, большие видео, и позволяет разобрать галерею свайпами.

Ключевые принципы:

- **Всё на устройстве.** Фото никогда не покидают телефон. Это главное обещание продукта, оно должно быть видно в онбординге и описании.
- **Быстро.** Галерея на 20–30 тыс. фото сканируется в фоне, интерфейс всегда плавный (60+ fps).
- **Безопасно.** Ничего не удаляется без явного подтверждения. Сначала пользователь собирает фото в «корзину Tazala», потом удаляет пачкой.
- **Честно.** Никаких обещаний «ускорить телефон», никаких фейковых предупреждений. Приложение полностью бесплатное: без покупок, подписок и рекламы.

Языки интерфейса: русский, казахский, английский (по умолчанию — язык системы, fallback — английский).

## 4. Функциональность MVP

### 4.1 Онбординг и разрешения
- 2–3 экрана: что делает приложение, «фото не покидают телефон», запрос доступа.
- iOS: корректно обработать полный доступ, **ограниченный доступ** (limited) и отказ. При limited — объяснить, что анализ будет неполным, и дать кнопку смены выбора.
- Android: `READ_MEDIA_IMAGES` и `READ_MEDIA_VIDEO` (API 33+), `READ_MEDIA_VISUAL_USER_SELECTED` для частичного доступа (API 34+), `READ_EXTERNAL_STORAGE` для старых версий.
- При отказе — экран с объяснением и кнопкой перехода в настройки.

### 4.2 Главный экран (дашборд)
- Сколько всего фото и видео, сколько места они занимают.
- Карточки категорий с количеством и объёмом: **Похожие фото**, **Дубликаты**, **Скриншоты**, **Размытые**, **Большие видео**.
- Прогресс сканирования, если оно идёт (с возможностью паузы).
- Большая кнопка **«Разобрать свайпами»**.
- Счётчик **«Освобождено с Tazala»** (накопительный).

### 4.3 Категории
- **Похожие фото** — группы (серии снимков). В каждой группе автоматически отмечено лучшее фото («Оставить»), остальные предложены к удалению. Пользователь может поменять выбор.
- **Точные дубликаты** — то же, но с одинаковыми картинками.
- **Скриншоты** — сетка с мультивыбором, сортировка по дате.
- **Размытые** — сетка, отсортированная по степени размытости.
- **Большие видео** — список, отсортированный по размеру, с длительностью и объёмом.
- Действия: «Выбрать всё», «Снять выбор», «В корзину Tazala».

### 4.4 Свайп-режим
- Выбор периода: по месяцам (например «Март 2024 · 412 фото») или «случайные».
- Карточка фото на весь экран: свайп влево — в корзину, вправо — оставить. Свайп вверх («в избранное», опционально) не реализован: на Android 11+ каждое изменение избранного требует отдельного системного подтверждения.
- Кнопка **«Отменить»** последнего действия.
- Хаптики, плавная анимация, предзагрузка следующих 3–5 изображений.
- Прогресс по месяцу; отметка разобранных месяцев.

### 4.5 Корзина Tazala и удаление
- Все отмеченные к удалению фото собираются во внутреннюю корзину (хранится в SQLite, ничего не удалено физически).
- Экран корзины: сетка, общий объём, кнопка **«Удалить N фото (X ГБ)»**.
- Удаление пачкой через системный API (см. 6.4). После успеха — обновить счётчик освобождённого места.
- **iOS:** после удаления показать подсказку, что фото попали в «Недавно удалённые» системного приложения «Фото» и место освободится после их очистки (или через 30 дней).

### 4.6 Настройки
- Язык, тема (система/светлая/тёмная).
- Чувствительность поиска похожих (3 уровня).
- Порог «большого видео» (например 50 / 100 / 200 МБ).
- Пересканировать галерею.
- Политика конфиденциальности (экран внутри приложения).

## 6. Нативный модуль `tazala-scanner`

### 6.1 TypeScript-интерфейс (контракт)

Актуальный контракт — `modules/tazala-scanner/src/TazalaScanner.types.ts` и `TazalaScannerModule.ts`. Кратко:

```ts
type MediaType = 'photo' | 'video';
type PermissionStatus = 'granted' | 'limited' | 'denied' | 'undetermined';

interface AssetInfo {
  id: string;            // localIdentifier (iOS) / MediaStore _ID (Android)
  uri: string;           // ph://… (iOS) / content://… (Android) — для expo-image
  mediaType: MediaType;
  createdAt: number;     // ms epoch
  modifiedAt: number;
  width: number;
  height: number;
  fileSize: number;      // bytes
  fileSizeEstimated: boolean;
  duration?: number;     // seconds, для видео
  isScreenshot: boolean;
  isFavorite: boolean;
}

interface LibraryStats { photoCount: number; videoCount: number; }   // общий объём считается в JS из таблицы assets

interface ScanOptions {
  assetIds?: string[];  // какие фото анализировать (JS вычисляет устаревшие по modifiedAt и analysisVersion); без него — все фото
  batchSize?: number;   // по умолчанию 100
  concurrency?: number; // 1–4, по умолчанию 3
}

interface AssetAnalysis {
  id: string;
  status: 'ok' | 'cloud-only' | 'failed';
  fingerprint: string | null;               // base64: featureprint rev2 в float16 (iOS 17+, устройство) или 64-bit dHash
  fingerprintKind: 'vision-v1' | 'dhash-v1' | null;
  blurScore: number;                        // дисперсия лапласиана на 256 px, больше = резче
  exactHash: string;                        // base64 сигнатуры 16×16 в оттенках серого (для точных дубликатов)
  analysisVersion: number;
}

interface GroupingOptions { databasePath: string; level: 'low' | 'medium' | 'high'; windowMs?: number; }
interface GroupingResult { groups: string[][]; duplicates: string[][]; comparisons: number; itemCount: number; durationMs: number; }
interface DeleteResult { deletedIds: string[]; failedIds: string[]; missingIds: string[]; cancelled: boolean; }

// Константы
platform: 'ios' | 'android'; moduleVersion: string; analysisVersion: number; fingerprintKind: 'vision-v1' | 'dhash-v1';

// Методы
getPermissionStatus(): Promise<PermissionStatus>;
requestPermission(): Promise<'granted' | 'limited' | 'denied'>;
presentLimitedLibraryPicker(): Promise<void>;          // iOS — системный пикер; Android 14+ — повторный запрос
getLibraryStats(): Promise<LibraryStats>;
listAssets(offset: number, limit: number): Promise<AssetInfo[]>;
startScan(options: ScanOptions): Promise<void>;        // результаты приходят событиями
pauseScan(): void; resumeScan(): void; cancelScan(): void; isScanning(): boolean;
findSimilarGroups(options: GroupingOptions): Promise<GroupingResult>;  // читает отпечатки напрямую из SQLite (read-only)
deleteAssets(ids: string[]): Promise<DeleteResult>;    // missingIds — уже отсутствующие в галерее
getMemoryUsage(): number;                              // для бенчмарка

// События
onScanProgress({ processed, total })
onScanBatch({ analyses: AssetAnalysis[] })
onScanComplete({ durationMs, processed, cancelled })
onScanError({ message })
onLibraryChange()                                      // PHPhotoLibraryChangeObserver / ContentObserver
```

Лучшее фото в группе выбирает JS (`src/features/scan/bestPick.ts`), а не натив.

### 6.2 Анализ изображений

Общие правила:
- Никогда не загружать полноразмерные изображения. Для анализа — миниатюра ~256–300 px по длинной стороне.
- Обработка на фоновом потоке/очереди, пачками, с ограничением параллелизма (2–4 потока), с проверкой флага отмены между пачками.
- Следить за памятью: освобождать bitmap/CGImage сразу после обработки (`autoreleasepool` на iOS, `recycle()`/переиспользование на Android).

**iOS:**
- Похожие фото: `VNGenerateImageFeaturePrintRequest`, расстояние через `computeDistance`. Порог для каждого уровня чувствительности сделать конфигурируемым и **откалибровать на тестовом наборе** (Фаза 1).
- Миниатюры через `PHImageManager` (300 px, `deliveryMode = .highQualityFormat` + `resizeMode = .fast`, синхронно на фоновой очереди, `isNetworkAccessAllowed = false`). `.fastFormat` отклонён: он отдаёт миниатюры разного размера, и оценка резкости становится несравнимой. Фото без локальной миниатюры помечаются `cloud-only`.
- Featureprint используется только на iOS 17+ (revision 2) и только на устройстве: на симуляторе Vision выдаёт вырожденные векторы, там используется dHash.
- Скриншоты: `PHAssetMediaSubtype.photoScreenshot`.

**Android:**
- Похожие фото: perceptual hash (dHash 64-bit, при необходимости pHash), сравнение по расстоянию Хэмминга. Пороги конфигурируемые и откалиброванные.
- Миниатюры через `ContentResolver.loadThumbnail` (API 29+) или `BitmapFactory` с `inSampleSize`.
- Скриншоты: по `RELATIVE_PATH` / `BUCKET_DISPLAY_NAME`, содержащему `Screenshots`.

**Обе платформы:**
- Размытость: дисперсия лапласиана на grayscale-миниатюре. Порог «размытое» калибруется; сортировка по `blurScore`.
- Точные дубликаты: сигнатура 16×16 в оттенках серого + совпадение размеров + допуск (макс. отклонение пикселя ≤ 8, среднее ≤ 2,5, отношение резкости ≤ 1,6). Жёсткое квантование в хеш отклонено: на калибровке оно ловило только 7 из 25 копий. Поиск — по корзинам размеров, отсортированным по средней яркости, без O(n²).
- Группировка похожих: только в **скользящем временном окне** (10 минут, параметр) и с **complete linkage** — фото входит в серию, только если оно похоже на все её фото. Транзитивное объединение (union-find) отклонено: оно склеивало всю галерею в одну цепочку.
- Пороги (калибровка `tools/calibration`, 25 сцен × 9 вариантов): Vision rev2 — low 0.40 / medium 0.55 / high 0.65; dHash — 6 / 10 / 14; размытость — `blurScore < 60`. Финальная калибровка Vision — на реальных сериях с устройства.
- Выбор лучшего фото в группе: избранное > максимальный `blurScore` > большее разрешение > более позднее.

### 6.3 Инкрементальность и кэш
- Результаты анализа хранятся в SQLite. При повторном запуске анализируются только новые или изменённые ассеты (`modifiedAt`), удалённые из галереи — вычищаются из кэша.
- В таблице хранить версию алгоритма (`fingerprintKind`, `analysisVersion`); при её смене — пересчитать.

### 6.4 Удаление
- **iOS:** `PHPhotoLibrary.shared().performChanges { PHAssetChangeRequest.deleteAssets(...) }` — одна системная конфирмация на пачку. Обработать отмену пользователем.
- **Android 11+ (API 30+):** `MediaStore.createDeleteRequest` → `PendingIntent` → результат через Activity Result. Одна конфирмация на пачку.
- **Android 10 (API 29):** обработать `RecoverableSecurityException`.
- **Android 8–9:** прямое удаление через `ContentResolver.delete` с соответствующим разрешением.
- Возвращать точный список удалённых и неудалённых id; UI обновляется только по фактически удалённым.

## 7. База данных (SQLite)

Схема и миграции — `src/db/migrations.ts` (версия в `PRAGMA user_version`, WAL, `foreign_keys = ON`):

```sql
assets (id PK, uri, media_type, created_at, modified_at, width, height, file_size,
        file_size_estimated, duration, is_screenshot, is_favorite, seen_generation);
analysis (asset_id PK → assets ON DELETE CASCADE, status, fingerprint TEXT (base64), fingerprint_kind,
          exact_hash, blur_score, analysis_version, analyzed_modified_at, analyzed_at);
similar_groups (group_id, kind 'similar'|'duplicate', asset_id → assets, is_best, PK(kind, group_id, asset_id));
swipe_decisions (asset_id PK → assets, decision 'keep'|'trash', decided_at);
trash (asset_id PK → assets, added_at, source);
stats (key PK, value);      -- freedBytes, deletedCount, lastScanAt
settings (key PK, value);   -- language, theme, similarityLevel, largeVideoMb, onboardingCompleted
```

Индексы: `assets(created_at)`, `assets(file_size)`, `assets(media_type, created_at)`, `analysis(exact_hash)`, `analysis(blur_score)`, `similar_groups(asset_id)`.

Удалённые из галереи ассеты вычищаются по `seen_generation` после каждой синхронизации (каскадом уходят анализ, группы, корзина и решения свайпов).

## 8. Производительность (целевые показатели)

Проверять на реальных устройствах среднего уровня (не только флагманах и симуляторах):

- Полный первичный скан 20 000 фото: цель — до 3–5 минут на устройстве среднего уровня; интерфейс при этом отзывчив.
- Повторный (инкрементальный) скан при 100 новых фото: несколько секунд.
- Сетки и свайп-режим: стабильно 60 fps, без «белых» миниатюр при быстрой прокрутке.
- Пиковое потребление памяти при скане: без резких скачков, без OOM на устройствах с 3–4 ГБ RAM.
- Холодный старт до дашборда (с кэшем): до 2 секунд.

Сделать **экран бенчмарка** (скрытый, доступен в dev-сборке), который показывает время скана, скорость (фото/сек), память и количество найденных групп.

## 10. Фазы работы

После каждой фазы — отчёт и ожидание подтверждения.

### Фаза 0. Каркас
- Expo-проект с TypeScript strict, New Architecture, expo-router, oxlint + oxfmt, Jest.
- Dev build для iOS и Android запускается.
- Скелет `modules/tazala-scanner` с одним тестовым методом, вызываемым из JS на обеих платформах.
- **Критерий:** приложение собирается и запускается на обеих платформах, тестовый нативный метод возвращает значение.

### Фаза 1. Нативный сканер (главный риск)
- Разрешения, `getLibraryStats`, `listAssets`, `startScan` с событиями, отмена/пауза.
- Featureprint (iOS) / dHash (Android), blurScore, exactHash, группировка похожих с временным окном.
- Экран бенчмарка.
- Сравнить производительность миниатюр через `expo-media-library` + `expo-image` против нативной загрузки; выбрать подход.
- Калибровка порогов: предложи методику (например тестовый набор из серий, дубликатов и разных фото) и подбери значения для трёх уровней.
- Unit-тесты для алгоритмов хеширования и расстояний (Kotlin — JUnit, Swift — XCTest, где это возможно без устройства).
- **Критерий:** на реальной галерее ≥ 5 000 фото скан проходит без крашей, группы похожих выглядят адекватно, цифры бенчмарка в отчёте.

### Фаза 2. Данные
- SQLite-схема, миграции, репозитории, инкрементальный скан, очистка кэша от удалённых ассетов.
- zustand-сторы, связка событий сканера с БД (запись пачками в транзакциях).
- **Критерий:** повторный запуск не пересчитывает уже проанализированное; данные переживают перезапуск.

### Фаза 3. Основной UI
- Онбординг, разрешения (включая limited/частичный доступ), дашборд, экраны всех категорий с мультивыбором.
- Тема, токены, базовые компоненты.
- **Критерий:** весь путь «установил → дал доступ → увидел категории → выбрал фото» работает на обеих платформах.

### Фаза 4. Свайп-режим
- Выбор месяца, карточки, жесты, отмена, хаптики, предзагрузка, прогресс.
- **Критерий:** 60 fps на устройстве среднего уровня, решения сохраняются.

### Фаза 5. Корзина и удаление
- Корзина Tazala, пакетное удаление на всех поддерживаемых версиях Android и iOS, обработка отмены и частичного успеха, счётчик освобождённого места, подсказка про «Недавно удалённые» на iOS.
- **Критерий:** удаление проверено на iOS и минимум на двух версиях Android (≤ 10 и ≥ 11); ничего не удаляется без системного подтверждения.

### Фаза 6. Локализация и полировка
- Полные переводы ru / kk / en (казахский — пометь места, где нужна вычитка носителем).
- Пустые состояния, ошибки, iCloud-фото без локальной копии, анимации, доступность, настройки.
- **Критерий:** нет захардкоженных строк, все экраны проверены на трёх языках и в обеих темах.

### Фаза 7. Монетизация — отменена
- Приложение полностью бесплатное: без покупок, подписок, пейвола и рекламы.

### Фаза 8. Подготовка к релизу
- Privacy manifest (`PrivacyInfo.xcprivacy`) для iOS, Data safety для Google Play — «данные не собираются».
- Тексты описаний в сторах на трёх языках (без обещаний «ускорения»), подсказки по скриншотам.
- EAS Build / EAS Submit конфигурация, версионирование.
- Чек-лист соответствия App Store Review Guidelines для утилит.
- **Критерий:** production-сборки для обоих сторов собираются, чек-лист пройден.

## 11. Что НЕ делать в MVP

- Никакого бэкенда, аккаунтов, облачной синхронизации.
- Никакой загрузки фото куда-либо, включая «AI в облаке».
- Не чистить кэш приложений, контакты, файлы — только фото и видео.
- Не делать сжатие фото/видео (возможно, позже).
- Не использовать формулировки «ускорит телефон», «вирусы», «перегрев» и подобные.
